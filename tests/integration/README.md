# s3sweep Integration Tests

Integration tests for the s3sweep S3 file transfer system using MinIO and Toxiproxy for local testing.

## Prerequisites

- Docker and Docker Compose
- rclone (`brew install rclone` or similar)
- MinIO client (`brew install minio/stable/mc`)
- bash 4.0+
- jq (for JSON parsing)

## Quick Start

```bash
# 1. Start test environment
cd tests/integration
docker-compose up -d

# 2. Setup test data and configuration
./setup.sh

# 3. Run end-to-end tests
./test_e2e.sh

# 4. Run multi-worker tests
./test_multiworker.sh

# 5. Cleanup
docker-compose down
```

## Test Environment

### MinIO (S3 Compatible Storage)

- **Endpoint**: http://localhost:9000
- **Console**: http://localhost:9001
- **Credentials**: minioadmin / minioadmin
- **Test Bucket**: s3sweep-test

### Toxiproxy (Network Chaos Testing)

- **API**: http://localhost:8474
- **Proxy Port**: 19000 → MinIO:9000

Use for simulating network issues:
```bash
# Add latency
curl -X POST http://localhost:8474/proxies/minio/toxics \
  -d '{"type":"latency","attributes":{"latency":1000}}'

# Reset
curl -X DELETE http://localhost:8474/proxies/minio/toxics/latency
```

## Test Suites

### End-to-End Tests (`test_e2e.sh`)

| Test ID | Name | Description |
|---------|------|-------------|
| INT-001 | Successful Download | Valid job downloads file to destination |
| INT-002 | File Not Found | Non-existent S3 key → failed state |
| INT-003 | Multiple Jobs Sequential | 10 jobs processed in sequence |
| INT-004 | Job State Transitions | pending → processing → done |
| INT-005 | Failed Job Retry | Move from failed back to pending |
| INT-006 | Different File Sizes | 1KB, 1MB, 100MB files |
| INT-007 | Rclone Config Validation | Verify remote configuration |
| INT-008 | Concurrent File Access | Multiple jobs, same destination |

### Multi-Worker Tests (`test_multiworker.sh`)

| Test ID | Name | Description |
|---------|------|-------------|
| INT-009 | Single Job Multiple Workers | 3 workers, only 1 claims job |
| INT-010 | 100 Jobs 3 Workers | All processed, no duplicates |
| INT-011 | No Duplicate Processing | Each job processed exactly once |
| INT-012 | Fair Distribution | Jobs evenly distributed |
| INT-013 | Staggered Start | Workers start at different times |
| INT-014 | Worker Sharding | Jobs distributed by worker ID |
| INT-015 | Job Timeout | Stuck jobs recovered |

## Test Data

The `setup.sh` script creates these test files in MinIO:

- `test/test.txt` - Small text file (27 bytes)
- `test/file_1kb.bin` - 1KB binary file
- `test/file_1mb.bin` - 1MB binary file
- `test/file_100mb.bin` - 100MB binary file

All files are uploaded to the `s3sweep-test` bucket.

## Rclone Configuration

Test configuration is generated at `tests/integration/rclone.conf`:

```ini
[s3test]
type = s3
provider = Minio
env_auth = false
access_key_id = minioadmin
secret_access_key = minioadmin
endpoint = http://localhost:9000
```

## Writing New Tests

### Basic Test Structure

```bash
#!/bin/bash
set -euo pipefail

SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"
source "$SCRIPT_DIR/../lib/helpers.sh"
source "$SCRIPT_DIR/../lib/assertions.sh"

test_my_new_feature() {
    test_section "INT-XXX: My New Feature"

    setup_test_env

    # Your test logic here
    create_job "my-job" "job-id|s3test|bucket/path|/dst/path"

    # Assertions
    assert_job_succeeded "my-job"

    local result=$?
    cleanup_test_env
    return $result
}

main() {
    reset_assertions
    test_my_new_feature || ((failed++))
    print_assertion_summary
}

main "$@"
```

### Available Helpers

**Environment Setup:**
- `setup_test_env()` - Create temp directories and config
- `cleanup_test_env()` - Clean up test environment
- `create_job(name, content)` - Create job file in pending/

**Assertions:**
- `assert_file_exists(path)`
- `assert_file_in_dir(filename, dir)`
- `assert_job_succeeded(job_name)`
- `assert_job_failed(job_name)`
- `assert_checksum_match(file1, file2)`
- `assert_equals(actual, expected)`
- `assert_greater_than(actual, threshold)`

**Logging:**
- `test_info(message)` - Info message (green)
- `test_error(message)` - Error message (red)
- `test_section(title)` - Section header

## Troubleshooting

### MinIO not starting

```bash
# Check logs
docker-compose logs minio

# Restart services
docker-compose restart
```

### rclone config issues

```bash
# Test rclone config manually
rclone lsd s3test: --config tests/integration/rclone.conf

# List bucket contents
rclone ls s3test:s3sweep-test --config tests/integration/rclone.conf
```

### Port conflicts

If ports 9000/9001 are already in use, edit `docker-compose.yaml`:

```yaml
ports:
  - "19000:9000"  # Change external port
  - "19001:9001"
```

### Cleanup stuck resources

```bash
# Remove all test containers and volumes
docker-compose down -v

# Remove test data
rm -rf tests/integration/testdata
rm -f tests/integration/rclone.conf
```

## CI/CD Integration

### GitHub Actions Example

```yaml
name: Integration Tests

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Install dependencies
        run: |
          sudo apt-get update
          sudo apt-get install -y rclone
          curl -O https://dl.min.io/client/mc/release/linux-amd64/mc
          chmod +x mc
          sudo mv mc /usr/local/bin/

      - name: Start test environment
        run: |
          cd tests/integration
          docker-compose up -d
          ./setup.sh

      - name: Run E2E tests
        run: ./tests/integration/test_e2e.sh

      - name: Run multi-worker tests
        run: ./tests/integration/test_multiworker.sh

      - name: Cleanup
        if: always()
        run: |
          cd tests/integration
          docker-compose down -v
```
